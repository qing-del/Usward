# Usward 正式前端（单人功能）

`frontend/` 是 Vue 3 + TypeScript + Vite 应用，视觉参照 `static/UI` 的 HTML 交互预览。它使用后端 Session 和 `/api/v1` 接口，不读取或迁移预览的浏览器演示数据。

## 本地运行

需要 Node.js 24.15+（或 22.22.2+）、Java 21 和 MySQL 8.4。先按 [后端运行说明](../docs/backend-setup.md) 启动服务并创建账号；正式前端没有演示账号或注册入口。

```sh
cd frontend
npm ci
npm run dev
```

打开 <http://127.0.0.1:5173/>。Vite 将同源 `/api/v1` 请求代理到 `http://127.0.0.1:8080`，因此浏览器中的 Session Cookie 和 CSRF 请求保持同一站点。修改代理目标时更新 `vite.config.ts`。生产部署需在同一 HTTPS 站点下把 `/api/v1` 转发到后端，并将其它应用路由回退到构建产物的 `index.html`；生产环境设置 `USWARD_COOKIE_SECURE=true`。

## 当前功能

- 登录、退出、修改密码，以及昵称、头像、显示时区、通知收件邮箱设置。
- 私人记忆的服务端搜索、筛选、分页、详情、创建、编辑、归档、恢复、删除。
- 个人日历的日程、周、月、1–93 天范围查询，以及个人安排的创建、编辑、删除。
- 私密承诺的服务端分页、筛选、详情、创建、编辑、完成、取消、重开和删除；可从自己的卡片或安排关联来源。
- 在记忆卡片、个人安排和进行中的承诺详情设置、重设或取消私人提醒；新建内容时也可附带设置，内容保存后提醒失败可以单独重试。
- 私人提醒清单支持内容类型、状态筛选及服务端分页；站内通知清单支持全部、未读、已读筛选、单条已读和按查询快照全部标为已读。
- “今天”通过一次 `/dashboard` 查询展示今日个人安排、到期承诺、最近一张记忆、前五条待触发提醒和快捷入口。顶栏展示后端返回的全量未读数，在页面重新可见时及可见期间每 60 秒刷新。

未接入的分享、连接、表达、邀约和邮件发送不会使用本地假数据展示。邮箱设置可以保存，但后端尚未启用邮件能力，提醒表单的邮件选项不可用，也不承诺站外送达；未连接时忙闲共享不可开启。记忆列表摘要没有正文，承诺列表摘要没有说明或完成记录，打开详情才请求这些内容。仅日期截止保留原时区；精确时间和提醒时间按账号时区输入，夏令时重复时间需选择偏移，不存在的当地时间不能提交。过去的提醒时间可以保存，之后由后端扫描处理。

## 验证

```sh
npm test
npm run build
```

`npm run build` 包含 TypeScript/Vue 类型检查，产物写入 `frontend/dist/`。测试覆盖 CSRF、401/409、列表分页、承诺状态、提醒修订与两步保存、通知单条及批量已读、快照失效、未读数账号切换、首页聚合、日历范围和夏令时转换。真实端到端验证需要运行中的 Java/MySQL 后端和两个独立账号：分别登录后确认私人卡片、日程、承诺、提醒及通知互不可见，刷新后数据仍在，修改密码后原会话失效，并确认到时只生成一次通知。

本轮本机验证（2026-10-03）：`npm test` 通过 13 个文件、45 个用例，`npm run build` 的类型检查与构建通过。使用临时模拟 `/api/v1` 在 320、768、1440 像素宽度检查了“今天”、提醒及通知页面，没有整页横向溢出；走通通知单条已读、批量已读、跳转卡片提醒控件、模拟账号切换与刷新。模拟乙账号看不到模拟甲的提醒和通知。本机缺少可用的 Java 运行时、MySQL 和 Docker，因此尚未运行真实后端联调；两个真实账号的数据隔离、刷新持久化和到时通知的唯一性仍待在可运行后端的环境验证。
