# Usward v1.3 HTML 交互预览

依据 [`docs/v1-design.md`](../../docs/v1-design.md) 制作。纯 HTML、CSS、JavaScript，无构建步骤、外部字体、CDN 或网络依赖。

## 打开预览

推荐在项目根目录运行：

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory static/UI
```

浏览器打开 <http://127.0.0.1:4173/>。

也可直接打开 `index.html` 查看页面；浏览器对 `file://` 的本地存储支持不同，完整的跨页数据保存和双账号演示请使用上面的本地 HTTP 服务。

| 页面 | 入口 | 内容 |
| --- | --- | --- |
| 今天 | `index.html` | 今日安排、待回应内容、私人提醒、承诺、三个快捷入口 |
| 日历 | `calendar.html` | 手机默认日程列表、周/月视图、个人安排、对方忙闲、邀约确认与共同改期 |
| 表达 | `expressions.html` | 六种轻量表达、收到/发出列表、回应与补充、撤回占位、关联邀约 |
| 记忆 | `memories.html` | 关键词/类别/标签筛选、编辑、整卡分享预览、补充/更正、归档与恢复 |
| 我的 | `me.html` | 资料、通知收件邮箱、私人提醒清单、时区、忙闲共享、站内通知与 Mail 状态、连接邀请、解除连接 |
| 我的承诺 | `commitments.html` | 创建自己的承诺、截止日期与时间、完成记录、取消/重新打开、主动分享 |
| 登录 | `login.html` | 演示登录、密码表单、两个账号切换、登录帮助 |

桌面使用侧栏，手机使用「今天 / 日历 / 表达 / 记忆 / 我的」底部导航。承诺入口只放在今天和我的。

## 演示账号与数据

- 首次打开载入林安的双人连接示例。
- 演示账号：`linan`（林安）、`chenyu`（陈屿）；使用任意非空演示密码。密码不保存。
- 在「我的」退出登录后切换账号，可从双方视角完成协商流程。两个视角分别保留草稿、私人提醒和通知。
- 改动保存在当前浏览器的 `localStorage`，刷新、跨页面导航后保留。存储不可用时会提示，修改只能保留在当前页面打开期间。
- 在「我的 → 预览设置」或桌面侧栏的「交互预览」中，可载入单人/双人示例。载入示例会替换当前预览修改。
- 在单人状态生成邀请时，页面只显示一次口令；请当场记录，再切换另一演示账号输入并接受。刷新后只能查看邀请编号、有效期，或撤销、重新生成。浏览器存储只保留口令摘要，不保存明文；口令不放进 URL。
- 页面加载、重新可见及可见期间会补查到期提醒；站内未读数量每 60 秒刷新，邮件演示每 10 秒推进处理状态。同一提醒修订不会重复生成站内通知或邮件任务。

## 邮箱提醒预览

为便于查看交互，本地预览默认模拟部署「已启用且配置完整」；正式部署仍按设计默认关闭邮件能力，由维护者配置后启用。

1. 在「我的 → 通知收件邮箱」设置本人演示地址，例如 `linan@example.com`。邮箱可清空，不作为登录账号，也不显示给对方。已有预览数据的提醒仍保持站内方式。
2. 在记忆卡片、个人/共同安排或自己的进行中承诺里，填写私人提醒时间，再选择「站内提醒」或「站内提醒 + Mail 提醒」。默认站内方式；不支持单独邮件。共享内容的双方独立设置，对方分享的承诺不能设置提醒。
3. 未设置邮箱、模拟邮件未启用或配置不完整时，邮件选项不可选并说明原因。保存时再次校验；错误时保留表单及选择，不自动降级。截止日期、事件开始时间不会自动创建提醒。
4. 使用一个已过去的提醒时间，可以立即体验到时补查。在「站内通知」查看独立的 Mail 状态和通用邮件内容预览：等待发送、正在处理、邮件服务器已接受、发送失败、已取消。服务器接受不代表到达收件箱或已读；标为已读不会取消邮件。
5. 在「预览设置 → 邮件提醒演示 → 演示设置」模拟部署能力和处理结果。临时失败按 1、5、15、60 分钟间隔重试，最多尝试 5 次；失败后恢复配置不会自动补发。这里只演示本地状态，没有用户重发功能、真实 SMTP 配置或凭据输入。

首页按时间列出最多 5 条待触发提醒，包含对方分享卡片、个人/共同事件和自己的承诺；「查看全部」或「我的 → 我的私人提醒」可查看完整清单。已触发与已取消的记录放在历史中，不会误显为未来计划。对已触发但邮件仍在等待或重试的提醒，可以通过「调整 / 取消提醒」清空时间后保存来停止未完成任务。

更换/清空邮箱只取消尚未完成的旧地址任务，不转投新地址，也不改变未来计划的时间和方式。再次设置提醒（包括只改方式或重设相同时间）会产生新修订并取消旧任务。完成/取消承诺、取消事件、删除内容、撤销分享和解除连接按权限清理提醒及未完成邮件；作者保留访问权限的私人提醒继续有效。重新打开、再次分享或建立新连接都不会恢复旧计划。共同改期保留原提醒设置，仅向有待触发提醒的人分别写入检查提示，不发改期邮件。

邮件内容只有通用主题、文案和网站入口，不包含资源标题、正文、回应、地点或取消说明。打开入口仍需要登录并检查资源访问权限。预览不会发送真实邮件；关闭网页期间没有后台执行，下次打开才补查到期计划，不能用于真实提醒服务。

## 建议体验流程

1. 用 `linan` 记一张卡片，刷新确认内容保留。新建默认「仅自己」及「我的理解，待确认」。
2. 预览整张卡片后主动分享。切换 `chenyu`，只会看到自己的卡片及对方已分享的卡片；可提交补充，不能直接编辑对方原文。
3. 用 `linan` 发出表达；切换 `chenyu` 回应，并从表达发起有明确时间的邀约。
4. 切回 `linan` 接受邀约。双方日历中形成同一条共同安排。时间冲突只显示时间段，接受时需要明确确认。
5. 用 `chenyu` 提出修改；在 `linan` 接受前原安排保持有效，接受后才替换。也可以拒绝、撤回或取消共同安排。
6. 为自己创建承诺、写完成记录、重新打开。另一方只能阅读主动分享的承诺。卡片和共同安排的私人提醒分别属于设置者。
7. 在「我的」解除连接，阅读影响说明并二次确认。双方个人卡片和承诺保留并恢复私密；旧表达、邀约、共同安排、分享及跨用户通知不可再从界面访问。新连接不继承旧内容。
8. 载入单人示例，不建立连接也能使用个人记忆、日历、承诺及提醒；表达和邀约入口会解释连接要求。

## 预览边界

这是用于审阅设计和交互的本地原型，没有调用后端 API，也不会向真实用户发送消息。

演示登录、连接、权限、提醒和通知由浏览器内的状态模拟。两个演示账号的数据共存在同一个浏览器存储中；它不是安全的多用户存储、真实 Session 认证或数据库事务实现。不要在预览中输入真实密码、私密关系内容或其他敏感数据。清除浏览器站点数据可以删除本地预览记录。

Java/Spring Security、MySQL 持久化、服务端鉴权、并发事务、生产提醒扫描、邮件队列租约、SMTP/TLS/认证与真实投递、HTTPS、备份与恢复等仍属于正式工程，不包含在这次 HTML 预览中。

## 已验证

- 七页加载、相对资源和主导航；JavaScript 语法。
- 320 / 768 / 1440 像素布局无横向溢出，手机五项底部导航、默认日程列表与窄屏表单。
- 新建记忆、搜索、整卡分享、对方只读与补充。
- 自由留言必填、关闭后草稿恢复、回应、撤回后不显示正文与回应。
- 个人全天安排、全天邀约、邀约冲突确认、双账号的表达 → 回应 → 邀约 → 接受 → 改期确认流程。
- 承诺完成记录、重新打开和对方只读。
- 忙闲开关、主动分享标题且备注保持私密、双账号一次性口令接受、不能自接受、解除连接及新连接隔离。
- 收件邮箱与邮件选项、三类资源的组合提醒、通知与邮件状态独立、修订去重、改邮箱、失败与有限重试、双账号隔离、撤销分享/解除/资源关闭清理。自动回归覆盖 24 个本地状态场景，不代表通过真实 SMTP 或数据库并发验收。

```sh
node --test static/UI/tests/reminders.test.cjs
```
