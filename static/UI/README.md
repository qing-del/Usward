# Usward v1 HTML 交互预览

依据 [`docs/v1-design.md`](../../docs/v1-design.md) 制作。纯 HTML、CSS、JavaScript，无构建步骤、外部字体、CDN 或网络依赖。

## 打开预览

推荐在项目根目录运行：

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory static/UI
```

浏览器打开 <http://127.0.0.1:4173/>。

也可直接打开 `index.html` 查看页面；浏览器对 `file://` 的本地存储支持不同，完整的跨页数据保存和双账号演示请使用上面的本地 HTTP 服务。

| 页面 | 入口 | 内容 |
| --- | --- | --- |
| 今天 | `index.html` | 今日安排、待回应内容、私人提醒、承诺、三个快捷入口 |
| 日历 | `calendar.html` | 手机默认日程列表、周/月视图、个人安排、对方忙闲、邀约确认与共同改期 |
| 表达 | `expressions.html` | 六种轻量表达、收到/发出列表、回应与补充、撤回占位、关联邀约 |
| 记忆 | `memories.html` | 关键词/类别/标签筛选、编辑、整卡分享预览、补充/更正、归档与恢复 |
| 我的 | `me.html` | 资料、时区、忙闲共享、站内通知、连接邀请、解除连接 |
| 我的承诺 | `commitments.html` | 创建自己的承诺、截止日期与时间、完成记录、取消/重新打开、主动分享 |
| 登录 | `login.html` | 演示登录、密码表单、两个账号切换、登录帮助 |

桌面使用侧栏，手机使用「今天 / 日历 / 表达 / 记忆 / 我的」底部导航。承诺入口只放在今天和我的。

## 演示账号与数据

- 首次打开载入林安的双人连接示例。
- 演示账号：`linan`（林安）、`chenyu`（陈屿）；使用任意非空演示密码。密码不保存。
- 在「我的」退出登录后切换账号，可从双方视角完成协商流程。两个视角分别保留草稿、私人提醒和通知。
- 改动保存在当前浏览器的 `localStorage`，刷新、跨页面导航后保留。存储不可用时会提示，修改只能保留在当前页面打开期间。
- 在「我的 → 预览设置」或桌面侧栏的「交互预览」中，可载入单人/双人示例。载入示例会替换当前预览修改。
- 邀请口令只在表单中输入，不放进 URL。可在单人状态生成口令，再切换另一账号接受；也可使用页面展示的示例口令。
- 网页可见时每 60 秒检查站内提醒；重新打开时补查到期提醒，同一提醒计划不会重复生成通知。

## 建议体验流程

1. 用 `linan` 记一张卡片，刷新确认内容保留。新建默认「仅自己」及「我的理解，待确认」。
2. 预览整张卡片后主动分享。切换 `chenyu`，只会看到自己的卡片及对方已分享的卡片；可提交补充，不能直接编辑对方原文。
3. 用 `linan` 发出表达；切换 `chenyu` 回应，并从表达发起有明确时间的邀约。
4. 切回 `linan` 接受邀约。双方日历中形成同一条共同安排。时间冲突只显示时间段，接受时需要明确确认。
5. 用 `chenyu` 提出修改；在 `linan` 接受前原安排保持有效，接受后才替换。也可以拒绝、撤回或取消共同安排。
6. 为自己创建承诺、写完成记录、重新打开。另一方只能阅读主动分享的承诺。卡片和共同安排的私人提醒分别属于设置者。
7. 在「我的」解除连接，阅读影响说明并二次确认。双方个人卡片和承诺保留并恢复私密；旧表达、邀约、共同安排、分享及跨用户通知不可再从界面访问。新连接不继承旧内容。
8. 载入单人示例，不建立连接也能使用个人记忆、日历、承诺及提醒；表达和邀约入口会解释连接要求。

## 预览边界

这是用于审阅设计和交互的本地原型，没有调用后端 API，也不会向真实用户发送消息。

演示登录、连接、权限、提醒和通知由浏览器内的状态模拟。两个演示账号的数据共存在同一个浏览器存储中；它不是安全的多用户存储、真实 Session 认证或数据库事务实现。不要在预览中输入真实密码、私密关系内容或其他敏感数据。清除浏览器站点数据可以删除本地预览记录。

Java/Spring Security、MySQL 持久化、服务端鉴权、并发事务、生产提醒扫描、HTTPS、备份与恢复等仍属于正式工程，不包含在这次 HTML 预览中。

## 已验证

- 七页加载、相对资源和主导航；JavaScript 语法。
- 320 / 768 / 1440 像素布局无横向溢出，手机五项底部导航、默认日程列表与窄屏表单。
- 新建记忆、搜索、整卡分享、对方只读与补充。
- 自由留言必填、关闭后草稿恢复、回应、撤回后不显示正文与回应。
- 个人全天安排、全天邀约、邀约冲突确认、双账号的表达 → 回应 → 邀约 → 接受 → 改期确认流程。
- 承诺完成记录、重新打开和对方只读。
- 忙闲开关、主动分享标题且备注保持私密、双账号一次性口令接受、不能自接受、解除连接及新连接隔离。

每个页面完成时均有独立 Git 提交；后续共用逻辑和整体验证调整另外提交。
